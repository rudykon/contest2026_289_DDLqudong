# GPU 扩展与主线程优化

2026-09-23 整理，实板日志生成于 9 月 22 日。SF32LB52 黄山派，当前 openvela/LVGL 9 RGB565，390×450 屏幕。已烧录校验的候选固件为 5,871,668 B，SHA256 `8c10639d5f501d31f114a1f38396bd08515cdec1eaca440a0b8360ccfacb329f`。比上轮 EPIC 固件增加 7,560 B。

## 实现

- EPIC 从不透明填充、RGB565 复制扩展到单色 A8 掩码与整体透明度混合，覆盖达到 1,024 像素的部分字形及圆角最终混合块。小块继续使用软件；不是所有文字或所有绘制都进入 GPU。渐变/变换的生成仍在 LVGL 软件路径。
- A8 字节作为硬件 L8 调色板索引，将 LVGL 的 RGB565 五位透明度量化编码进 256 项 ARGB 调色板，避免 CPU 遍历转换每个掩码像素。窄区域按行维护缓存，成功后用半字复制提交输出。
- 每个硬件块最多 4,096 像素。透明混合先写 8 KiB SRAM 暂存区，成功后提交；失败时只软件绘制尚未完成的后缀，防止透明度重复叠加。硬件仍同步轮询，单 GUI 绘制线程；不是异步 GPU 队列。
- 停止训练立即停止采样、取消推理并显示保存状态；总结、图表、建议、元数据、界面、存储提交分为六个事件循环任务。保存回调之前不能开始、重置、清空或发送旧记录；销毁页面时补交已接受的保存任务，过期回调不再修改页面。分阶段让出主线程，不等于 JS 已移到工作线程。
- openvela 原生 `storage_impl.cpp` 原来在入口将整个 JSON 输出至串口，改为仅输出 key 和长度，保留原有 `uv_db_set` 异步语义。对应可重放补丁为 `prepare-runtime-latency-linux.py`，资源构建和完整构建都会应用。应用保存格式不变。

## 同一镜像对照

`expanded-final-off/on` 均保留基础 EPIC，只切换新增掩码路径；每轮重启，22 次合成操作，启用相同阶段计时并等待保存完成。原始日志在 `../logs/`，汇总为 [expanded-comparison.json](expanded-comparison.json)。

| 操作 | 掩码关闭 | 掩码开启 |
|---|---:|---:|
| 快应用缓存切页，4 次中位数 | 454.5 ms | 454 ms |
| 训练中切页，8 次中位数 | 615.5 ms | 595 ms |
| 开始训练，1 次 | 771 ms | 776 ms |
| 冷启动，1 次 | 5759 ms | 5776 ms |
| 停止反馈，1 次 | 540 ms | 547 ms |
| 停止入口至保存回调 | 838 ms | 857 ms |
| 停止入口至最终界面字段提交 | 882 ms | 905 ms |

新 GPU 路径实测完成 86 个混合块，运行 faults=0，最长单块关中断 2,079 μs。普通切页没有实质改善；训练切页样本存在调度波动，不能把 20.5 ms 差值全部归因于 GPU。独立微基准中，重复处理 780 字节步幅、64 像素宽的掩码，GPU 比热缓存 CPU 慢（例如稠密 2,048 像素 CPU 350 μs、GPU 681 μs）。因此本轮成果是扩展并验证覆盖，**没有证明掩码 GPU 普遍提速**；小块仍由 CPU 处理。原有大面积填充收益见上轮报告。

主线程方面，上轮 `epic-stop-trace-on` 的松开事件处理为 635 ms、停止反馈 1157 ms；新版两轮停止反馈 540/547 ms。新任务正常阶段耗时为总结 5–6、图表 25–26、建议 20、元数据 4、界面 15、保存提交 50 ms。移除完整 JSON 串口输出前，提交阶段曾为 479 ms；最终为 50 ms，其中序列化 35 ms、原生提交 9–10 ms。这个前后对照涉及不同固件，不能解释为 GPU 单项收益。

诊断中的 `expanded-storage-probe` 曾测到建议阶段 410 ms；后续两轮为 20 ms。该异常原因尚未确定，未将其隐去或声称所有任务都已有严格耗时上限。停止后的界面重排与事件调度仍有成本，冷启动约 5.8 秒、训练翻页约 0.6 秒，**整体尚未达到市售手表流畅度**。

以上为合成 LVGL 按下至变更页面刷新完成，包含约 100 ms 按压及调度延误，不含真实触摸采样和面板响应。保存完成另从停止函数入口计时，最终字段提交也不等于屏幕完成刷新。`persisted=true` 仅代表当前存储 API 成功回调：本固件 NOR 写擦仍禁用，未实现断电保存，清单 `storage_persistent=false` 保留。

## 正确性与复测

9 项填充/复制/回退自测，加 7 项掩码/整体透明度/失败不提交自测均通过；全缓冲区保护字节和行填充保持，透明像素与软件的最大差异为 RGB565 单通道 1 级量化误差。测试故障在提交前注入，没有验证物理总线卡死恢复。运行错误统计在自测后清零。

54 项核心测试、7 项手势测试，以及实时字段、特征切片、页面状态和新增协作式停止测试通过。停止测试覆盖回调前忙状态、重复回调、保存失败、场景快照、页面销毁和过期任务。

字体 Regular/Demibold 合计仍为 2,076,708 B，两份 SHA256 保持不变；字号及粗体保持。镜像仅包含 `com.velamotion.coach`，LVGL 演示符号仍不在镜像。详见 `font-subset-image-checks.json` 和 `size-firmware.json`。

六张板端渲染截图均通过四角 80×65 区域检查。工具页与旧画面差 490 像素、应用首页差 356 像素，最大 RGB565 通道差均为 1；手势往返教练页像素完全一致。同镜像工具页掩码开关也仅有相同 490 像素的一级差异。旧的“必须零像素差异”脚本因此不适用于新透明混合路径，使用显式限制一级量化误差的 `verify-expanded-images.py`，没有放宽布局差异。证据为 `expanded-pixel-comparison.json`、`expanded-corner-audit.json`。这些是板端渲染截图，不是物理面板照片。显示验收后空闲堆 5,443,848 B。

复测：`benchmark-ui.ps1 -Reset -Trace -WaitFinalize -GpuMode on -GpuMaskMode off/on -Name <name>`。`gpu mask bench` 是独立微基准，计数不代表界面帧数。`analyze-expanded.py` 分开汇总界面反馈与保存回调。

本轮之前的可回退固件为 `../firmware/velamotion-before-epic-expanded.bin`，配套清单 `../manifest-before-epic-expanded.json`。工作环境和依赖继续使用 D 盘 WSL。
