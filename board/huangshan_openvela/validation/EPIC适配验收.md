# 黄山派 EPIC → openvela/LVGL 适配

2026-09-22。EPIC 已接入当前 LVGL 9 RGB565 绘制路径并烧录，默认启用。它缩短了大面积绘制，但**尚未达到市售手表的整体流畅度**。当前接入是填充和复制子集，没有宣称字体、透明混合、旋转等操作全部使用 GPU。

## 实现范围

- `vmc_epic_hw.c/.h` 在 NuttX arch 内调用现有 SiFli HAL；`vmc_epic_lvgl.cpp` 通过链接器 wrap 接入两个 RGB565 软件混合入口，不修改上游 LVGL/HAL 源码。`install-epic-linux.py` 由完整构建的 `prepare-app-linux.py` 自动调用。
- 不透明、无掩码的 RGB565 填充达到 16,384 像素时使用 EPIC。普通 RGB565 RAM 图像复制达到 4,096 像素且源目标不重叠时使用 EPIC。更小的区域保留软件路径，避免启动及缓存维护成本反而变慢。
- 文字、透明混合、掩码、渐变、旋转/缩放及 Flash XIP 源图像仍由现有软件路径处理。当前产品界面实测命中的是大面积填充；复制能力通过独立实板自测验证，界面基准中复制计数为 0。
- 每批最多 4,096 像素，批次间恢复中断；提交前清理缓存、完成后使目标缓存失效。临界区保护同一缓存行内相邻字节。检查 RAM 范围、偶数地址/步幅、矩形大小和复制重叠。
- 使用 HAL 的 IT 启动入口，但不向 NVIC 开放 EPIC IRQ；同步轮询状态及 EOF 完成标志，再调用 HAL 完成处理。带周期计数器期限，不采用 HAL 无界等待。这不是 CPU 与 GPU 并行执行的异步绘制队列。
- 当前 LVGL 软件绘制单元数为 1，所有入口及控制命令都在 GUI 线程执行。本实现不适用于未经同步的多绘制线程。未提高 CPU、Flash 或屏幕时钟。

## 同一固件开关对照

`verify-epic.ps1` 共 6 次重新启动、124 次合成操作；桌面两轮，快应用按 off/on/on/off 顺序四轮。每次启动的 9 项自测通过，运行 GPU 错误计数均为 0。原始证据是 `../logs/epic-final-*.log` 和对应 JSON，汇总为 `epic-comparison.json`。

| 操作 | GPU 关闭 | GPU 开启 | 样本 |
|---|---:|---:|---|
| 已缓存的桌面页面切换 | 226 ms | 205.5 ms | 各 12 次，中位数，降低 9.1% |
| 快应用已缓存页面切换 | 473.5 ms | 450 ms | 各 8 次，中位数，降低 5.0% |
| 训练中切换页面 | 624.5 ms | 603 ms | 各 16 次，中位数，波动较大 |
| 开始训练 | 783.5 ms | 784 ms | 各 2 次，没有改善 |
| 冷启动快应用 | 5812.5 ms | 5795.5 ms | 各 2 次，基本无变化 |
| 首页停止训练 | 1014.5 ms | 1310.5 ms | 各 2 次，见下文 |

停止训练没有改善：关闭 GPU 为 766–1263 ms，开启为 1254–1367 ms；本组开启后的中位数反而更高，不能省略或当作加速成果。后台训练的同步计算、输入派发、布局及收尾仍造成明显等待；当前样本不足以把这一波动全部归因于 GPU。完整的返回、恢复等结果也保存在汇总中，不只报告变快的操作。

为核查停止阶段，另做两次重启、44 次操作的逐阶段计时，不混入上述低日志量基准。`epic-stop-trace-off/on-analysis.json` 中，关闭/开启 GPU 的停止总耗时为 1155/1157 ms，松开事件处理占 627/635 ms，布局累计 134/136 ms，绘制累计 155/153 ms。该动作的重绘主要是小块，GPU 不能显著缩短事件处理与布局。因此本轮没有证明停止变快，也没有把主对照中的较高数值直接判为 GPU 绘图本身变慢。两次追加运行同样自测通过、GPU faults=0；总计 8 轮重启和 168 次合成操作。

计时为板端合成 LVGL 按下至页面标志变化后的刷新完成，包含约 100 ms 合成按压及调度延误，不包括真实触摸采样和面板像素响应。不能当作物理触摸延迟或帧率。两种状态使用完全相同的镜像、RPK、字号和刷新模式；不把与旧镜像不同的代码布局误当作 GPU 收益。

## 独立图元基准与正确性

以下每项重复 10 次，包含硬件提交、轮询及缓存维护。证据 `../logs/epic-final-boot.log`：

| RGB565 区域 | CPU 填充 | EPIC 填充 | CPU 复制 | EPIC 复制 |
|---|---:|---:|---:|---:|
| 390×16 | 0.322 ms | 0.434 ms | 1.167 ms | 0.978 ms |
| 390×100 | 6.230 ms | 2.219 ms | 10.381 ms | 5.525 ms |
| 390×450 | 28.265 ms | 9.725 ms | 46.819 ms | 24.721 ms |

小块填充反而较慢，因此设有门槛。整屏填充约 2.9 倍、复制约 1.9 倍的图元速度不等于应用或帧率提高同样倍数。该基准直接调用硬件，包含低于产品启用门槛的区域。

9 项启动自测：4 种尺寸/步幅/偏移分别进行填充及复制，与 LVGL 软件输出比较整个分配区，包括前后保护字节、行间填充及非缓存行对齐的子矩形；第 9 项验证软件回退补全已部分绘制的区域。自测中的 `faults=1` 是故意注入的提交失败，之后清零。产品基准的 GPU 调用累计 3,356 个分块、13,036,176 像素，运行时 faults=0；这些是分块计数，不是帧数。

实际界面测试的最长单批临界区为 775 μs，包含复制的独立基准最大为 1,233 μs；当前系统时钟节拍 10 ms。最初整屏单次复制触发 10 ms 期限，已改为分块。早期诊断版在故障注入时强行复位正在传输的总线主机，出现间歇硬件异常；已取消这种注入方式，并补充 EOF 完成检查。最终版本反复重启通过。故障自测现在先完成一小段，再模拟提交失败；它验证回退覆盖，**不代表已经验证物理总线卡死时的恢复**。

## 画面与功能

板端六张 `epic-*.png` 均通过四角 80×65 区域留白审计。工具页和快应用待机首页与原来的字库精简版逐像素相同（差异 0）；左滑两页后右滑回初筛页的前后画面差异也为 0。证据为 `epic-corner-audit.json`、`epic-pixel-comparison.json` 及截图。大字号、粗体和原有手势没有改小或删除。

基准覆盖桌面工具、秒表、设置、快应用启停训练、训练中翻页、返回桌面及恢复；截图额外覆盖左右滑动。画面来自板端 LVGL 快照，不是实体屏幕照片，合成操作不能代替物理触摸验收。截图验收后空闲堆为 5,489,488 B，见 `../logs/epic-memory.log`。原有可选健康/震动/互联接口能力及存储持久性限制没有在本轮改变。

追加诊断结束后已停止训练、回到桌面、恢复 GPU 开启、关闭性能日志并同步时钟，串口已释放。最终空闲堆为 5,278,976 B，见 `../logs/epic-final-state.log`；这与刚启动应用后的截图内存状态不同。

## 镜像与复现

镜像 `../firmware/velamotion-openvela.bin` 为 5,864,108 B，SHA256 `e552b62f95e26b94012bc104c3cc448f0a2e18c09c6f6da2691a832605f0bbaa`，烧录地址 `0x12010000`，sftool `--verify` 通过。比上一版增加 11,888 B，分区仍剩 4,162,900 B。D 盘常用镜像与验收镜像同步。

RPK 保持 52,910 B，SHA256 `d670785ce8f1f0838887a7df398349ae8fc5b27305bd2e9758ea989a19d4f802`。两套中文字库、字号、粗体、手势和桌面工具保持原实现；ROMFS 仍只有本应用，LVGL 演示资源仍未打包，见 `font-subset-image-checks.json`。新增的固件体积主要来自 HAL EPIC 函数、接入层和自测诊断。

回退镜像 `../firmware/velamotion-before-epic.bin`，清单 `../manifest-before-epic.json`，SHA256 `9edcea850770cfe6079457262d75c80a0085f7bf1d3fcce8f6c554af5183e4f1`。不需要重新编译即可回退。临时诊断也可向 `/data/ui-command` 写入 `gpu off`；重启后恢复默认开启。`gpu on`、`gpu stats`、`gpu reset`、`gpu bench` 分别启用、读取计数、清零计数和执行阻塞式图元基准，只在设备空闲时运行基准。

```powershell
.\verify-epic.ps1
python .\analyze-epic.py
.\verify-latency-display.ps1 -Prefix epic
python .\verify-latency-images.py epic
```

源码/工具链、构建、依赖继续使用 D 盘 WSL。仅修改 EPIC 源码时，先在 WSL 运行 `install-epic-linux.py` 再执行 `cmake --build /opt/openvela/build -j6`；只运行 `--assets-only` 不会同步这些 C/C++ 源文件。
